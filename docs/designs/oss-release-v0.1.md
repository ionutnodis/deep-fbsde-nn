## Problem Statement

Turn the CQF final project — a working PyTorch library for solving high-dimensional PDEs/FBSDEs via the Deep BSDE method — into a public, open-source Python library that a researcher can install, trust, and cite. The code is good (clean `BaseEquation`/`BaseSolver` abstractions, NAIS-Net, MLMC time-stepping, polished README); the release infrastructure around it does not exist yet.

Positioning chosen in session: **the citable research library** — the maintained PyTorch deep-BSDE reference implementation. Not (yet) a quant practitioner XVA toolkit, not a general SciML framework.

## What Makes This Cool

The canonical deep-BSDE implementations (frankhan91/DeepBSDE, maziarraissi/FBSNNs) are TensorFlow and dormant. A pip-installable **PyTorch** library with NAIS-Net stability, MLMC training, exact-solution validation, and finance equations built in fills a real gap — and the core package already has zero heavy dependencies (verified: `deep_fbsde_nn/` imports only torch + numpy; matplotlib and scipy are used only outside the installed package — `experiments/`, plus lazy scipy imports in the root `tables.py` script; pandas, tqdm, and tensorboard are declared as dependencies but imported nowhere in the repo), so `pip install deep-fbsde-nn` can be genuinely lean.

## Constraints

- Solo maintainer; work happens in Claude Code sessions.
- Dev machine is Apple Silicon (MPS); CI is CPU-only Linux. Seeded torch RNG streams differ between MPS and CPU, so numeric tolerances are calibrated **in CI**, never locally.
- Public API (equations/networks/solvers/utils) should not break — README examples must keep working.
- XVA and greeks code is known-broken (commit e39091a) and must not block the release.

## Premises (agreed 2026-09-04)

1. **Release 0.1 proves correctness, not features.** Bar: tests validating solvers against known solutions, CI on every push, clean `pip install`. No new capabilities. (One reviewed exception: implementing `VanillaCallEquation.exact_solution` in-class — it fixes a shipped contradiction where README's API table says the equation has an exact solution and the code returns `None`.)
2. **XVA and greeks stay out of the tested surface.** Clearly marked experimental; headline of a future release.
3. **Repo hygiene precedes announcement.** One version number, one canonical URL, 16 MB of tracked binaries stop shipping to every clone. Distribution = PyPI + GitHub, CI as the pipeline.
4. **The niche is real: no maintained PyTorch deep-BSDE *library* owns it.** Verified 2026-09-04 (this closes T15): PyPI names `torchbsde`, `deepbsde`, `fbsde`, `deep-bsde`, `pytorch-bsde` are all unclaimed (only `deepxde` exists — PINNs, different method), and the GitHub sweep found several PyTorch deep-BSDE repos (YifanJiang233/Deep_BSDE_solver, batuhanguler/Deep-BSDE-Solver, zhoufy20/deep-bsde-pytorch, skyhehe123/DeepBSDE-pytorch) — all paper-reproduction research code, none packaged, tested, or maintained. The gap is not "no PyTorch implementation"; it is "no maintained, tested, installable library." The trust layer IS the differentiation.

## Approaches Considered

- **A) Straight to PyPI (minimal viable)** — ruled out: installable but not citable; release mechanics redone in 0.2.
- **C) Benchmark-first release (lateral)** — deferred, not rejected: the reproducible equation×dimension benchmark becomes the 0.2 headline.
- **B) Credible research release** — **chosen**: B contains A plus the trust-and-cite layer, staged so A's milestone ships midway.

## Recommended Approach

Approach B, four stages, each independently landable. Ordering constraints from review: CI skeleton stands up at the **start** of Stage 2; the NAIS-Net projection fix lands **before** convergence tolerances are calibrated.

### Stage 1 — Identity & hygiene
- Single-source the version at 0.1.0: `pyproject.toml` is truth; `deep_fbsde_nn.__version__` reads it via `importlib.metadata`, wrapped in `try/except PackageNotFoundError` with fallback `"0.0.0+unknown"` (git-clone users import without installing). Test asserts installed version == pyproject.
- **Safe checkpoint loading:** `BaseSolver.load` (`solvers/base.py:313`) switches to `torch.load(..., weights_only=True)` — the `add_safe_globals` scaffolding above it already exists for exactly this; today's `weights_only=False` executes arbitrary pickle code from any shared checkpoint. Round-trip test in Stage 2.
- Canonicalize all URLs (README install/clone, pyproject `[project.urls]`, BibTeX citation) to the chosen public repo name (release gate 2).
- Stop tracking committed junk: `git rm --cached` on `results/` (47 files, 16 MB), `.DS_Store`, `results/.DS_Store`, `experiments/__pycache__/*.pyc`. `.DS_Store` and `__pycache__/` are already gitignored (files predate the ignore); `results/` is only a commented-out `# results/` line (`.gitignore:47`) — uncomment it. History strategy is open question 2 (one-way door, own confirmation).
- Mark experimental code: move `experiments/exp_xva.py` into `experiments/experimental/`; extract greeks plotting (`plot_bs_greeks` in `experiments/visualize.py` + call sites) into `experiments/experimental/greeks_viz.py`. "Experimental" means a module-level `warnings.warn` at import plus a docstring note, not just a comment. All seven experiment scripts use `sys.path.insert(0, str(Path(__file__).parent.parent))` — moved scripts need `.parent.parent.parent` or the bootstrap silently breaks for clone-without-install users; also document `pip install -e .` in CONTRIBUTING. Delete the empty `experiments/run_all.py`.
- Root cleanup: delete `main.py` (a no-op demo superseded by the README); README truth pass — remove `results/` from the project-structure tree (about to be untracked), mention `tables.py`'s role or fold it under experiments, regenerate the dependency list from pyproject. Refresh the stale `__init__.py` docstring (version 1.0.0 reference, project framing).

### Stage 2 — Correctness layer (`tests/` + two code fixes)
- **CI skeleton first:** minimal `ci.yml` (ruff + pytest, Python 3.12, torch installed from `--index-url https://download.pytorch.org/whl/cpu` with pip caching — default Linux `pip install torch` pulls 2+ GB CUDA wheels) so every tolerance below is calibrated where it will run.
- **NAIS-Net projection fix (before calibration):** `_project` (`networks/naisnet.py:104-110`) rescales `WᵀW` by `sqrt(delta/norm)`, giving post-projection norm `sqrt(delta·norm)` — not < 1 for typical inits, contradicting the library's headline stability claim (and its own docstring line 19). Reconcile against Güler et al. (2019), implement the paper-correct linear rescale (`WtW * delta/norm`, norm exactly δ), replace the hardcoded `is_stable = True` property with a computed check, note that `torch.norm` is Frobenius (a conservative upper bound on spectral norm), add the norm-bound test, and rerun low-dim BSB validation to confirm training behavior held.
- `test_equations.py` — shapes for drift/diffusion/driver/terminal across all equations; BSB `exact_solution` sanity (t=T equals terminal); **`VanillaCallEquation.exact_solution` implemented in the equation class** via `torch.erf` (valid at D=1; `has_exact_solution()` true only for D=1) so `solver.validate()` works and the README API table stops contradicting the code — tests then exercise shipped code instead of a test-local duplicate.
- `test_networks.py` — forward shapes (NAISNet + FeedForward), activation registry incl. invalid-name error path, NAIS-Net norm-bound invariant, `networks/wrapper.py` shape test.
- `test_solvers.py` — MLMC schedule lookup; Brownian path statistics (E[ΔW]≈0, Var[ΔW]≈Δt); checkpoint save/load round-trip under `weights_only=True`; load-from-missing-file error path; chunked-training resume (optimizer + iteration counter preserved); `batch_size>1` and `dimension=1` paths; SolverConfig defaults; seeded determinism on CPU.
- `test_global_solver.py` — all four X0 sampling strategies (fixed/uniform/lognormal/gaussian) produce correct shapes and distributions; short training smoke.
- `test_utils.py` — `get_device` explicit preferences; metrics vs hand-computed values; checkpointing helpers.
- `test_convergence.py` (marked `slow`) — seeded StandardSolver on low-dimension BSB, reduced iteration budget, **loose correctness-level tolerance (rel. error ~1-2%), calibrated in CI, after the projection fix** — snapshot-tight tolerances would flake on every torch minor upgrade since `torch>=2.0.0` floats. Same for D=1 vanilla call vs its exact solution.
- **HJB convergence validation (CEO review D2.4):** validate against the shipped Cole-Hopf MC reference `HJBEquation.exact_solution` (`equations/hjb.py:98-159`) — do NOT re-implement test-locally. Preconditions: fix the chunking overcount at `hjb.py:132` (`current_n = min(chunk_size, n_mc)` draws `ceil(n_mc/10000)×10000` samples but divides by `n_mc` — biased whenever `n_mc` isn't a multiple of 10,000), seed the global RNG it draws from (`hjb.py:135`), and set the tolerance to cover MC standard error on top of solver error. Same CI-calibration ordering as the BSB test. After this, every equation with a known reference is validated; AllenCahn and the BS basket ship with shape tests only (recorded in TODOS.md).

## Build Log (v0.1 implementation, 2026-09-04)

Stages 1-3 built and verified in one session: **77 tests green (73 fast in ~1s, 4 slow convergence in 79s), ruff clean repo-wide, wheel+sdist build with `twine check` PASSED, quickstart runs end-to-end.** Tasks T1, T2, T4-T14, T16-T20 implemented (T3/gates remain user-only; Zenodo + trusted-publisher registration and URL canonicalization wait on gate 2; the real D=100 hero figure and JOSS submission are release-checklist items).

**Two production bugs found by the new convergence tests, beyond everything the reviews predicted:**
1. **StandardSolver integrated the driver with the wrong sign** (`standard.py`: `Y + φ·dt` where the documented convention — and GlobalSolver — use `Y − f·dt`). Every nonlinear equation trained through StandardSolver had its driver flipped. Fixed; both solvers now share the documented convention, and all five equations' drivers were standardized to it (BS/VanillaCall → `−rY`, AllenCahn → `Y − Y³`).
2. **The HJB driver had a factor-2 error**: it assumed `Z = σᵀ∇u = √2·∇u` while the solvers' `net_u` returns the raw `∇u`. Fixed to `−λ‖Z‖²`; validated by a finite-difference PDE-residual test of the Cole-Hopf reference (residual 4e-4 with the fix vs 1.7e-2/6.6e-2 for the factor/sign bugs).
